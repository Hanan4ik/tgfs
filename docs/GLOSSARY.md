# Термины TGFS простыми словами

Это учебное объяснение предложенной архитектуры, а не принятие всех её решений. Транспорт Bot API уже выбран; остальной формат обсуждаем в #2 и #3.

## Основа Linux

- **Ядро** — часть ОС, которая управляет ресурсами и обслуживает системные вызовы программ.
- **Системный вызов** — обращение программы к ядру: например открыть файл, прочитать байты или изменить имя. Это не запрос Telegram.
- **VFS** — общий слой файловых систем Linux. Программы используют привычные файловые операции независимо от места хранения.
- **FUSE** — механизм, через который ядро передаёт файловые запросы обычной программе. Наша программа определяет, где взять данные, а FUSE доставляет запросы и ответы. Сам FUSE ничего не знает о Telegram.
- **Daemon / демон** — работающая фоновая программа. Предлагаемый tgfsd обслуживает mount и обращается к Bot API.
- **Mount / монтирование** — подключение дерева файлов к каталогу Linux. /media/channel1 становится точкой входа в том.
- **Том** — отдельная файловая система с собственным деревом и идентичностью; профиль содержит настройки доступа к ней.
- **Файловый дескриптор** — номер открытого файла внутри программы; это не ID Telegram-сообщения.

Источник о FUSE: https://www.kernel.org/doc/html/latest/filesystems/fuse/fuse.html

## Формат TGFS

- **Данные** — байты содержимого, например текст notes.txt.
- **Метаданные** — сведения о файле: размер, тип, время, ссылки на части.
- **Inode** — объект файла с собственной идентичностью и метаданными. Имя хранится в записи каталога, связывающей имя с inode. Переименование не обязано менять идентичность.
- **Chunk / часть** — диапазон байт файла, который TGFS отправляет отдельным document.
- **Hash / хеш** — результат вычисления контрольного значения содержимого. SHA-256 помогает проверить целостность; это не имя или inode файла.
- **Каталог TGFS / manifest** — служебное оглавление: имена, папки, inode, версии, ссылки на части. Не путать полный каталог метаданных с одной папкой пользователя.
- **Индекс** — локально построенная таблица для быстрого поиска в оглавлении, кандидат реализации — SQLite.
- **Cache / кэш** — копии скачанных данных, которые можно получить снова.
- **Staging** — локальное место для ещё не опубликованной записи. Его нельзя очищать как обычный кэш.
- **Commit / фиксация** — публикация завершённого изменения TGFS. Это отдельное понятие от Git commit.
- **Generation / поколение** — номер подтверждённого состояния каталога.
- **Superblock** — в нашей схеме небольшой служебный заголовок тома: magic TGFS, версия формата, UUID тома, ссылка на актуальное состояние. Сам список файлов лежит отдельно. Это проектный аналог суперблока дисковой ФС, не структура, которую ядро напрямую читает из Telegram.
- **UUID** — идентификатор тома, inode или версии, не зависящий от имени профиля.
- **Атомарная видимость** — читатель видит целое старое либо целое новое состояние. Сам Telegram не предоставляет нам транзакцию сразу над несколькими сообщениями.
- **Backend** — часть TGFS, которая общается с хранилищем; сейчас выбран Bot API.
- **ADR** — короткий документ: какое решение принято, почему и какие ограничения остались.

## Операции и обработчики

Названия системных вызовов Linux и обработчиков FUSE не всегда совпадают один к одному.

| Операция | Смысл | Пример для TGFS |
| --- | --- | --- |
| open | Открыть файл и получить дескриптор | Найти inode notes.txt |
| read | Прочитать диапазон байт | Получить нужную часть из кэша или Telegram |
| write | Передать новые байты файловой системе | Поместить изменения в staging |
| stat / getattr | Узнать свойства | Вернуть размер и тип из индекса |
| readdir | Перечислить имена в папке | Взять список из каталога TGFS |
| mkdir | Создать папку | Добавить запись каталога |
| rename | Изменить имя или расположение | Поменять связь имени с inode |
| unlink | Удалить имя файла | Убрать запись; физическое удаление Telegram-документов — отдельно |
| truncate | Установить размер | Укоротить файл либо увеличить с соответствующей семантикой нулей |
| fsync | Дождаться фиксации изменений | Предлагаем ждать удалённой публикации полной версии |
| close | Закрыть дескриптор | Завершить использование файла; само по себе не универсальная гарантия удалённой сохранности |
| flush / release | Обработчики FUSE при закрытии и освобождении ресурсов | Не равны автоматически загрузке файла в Telegram |

В Linux fsync файла не обязательно фиксирует изменение имени в родительском каталоге: для этого нужен fsync каталога. Источник: https://man7.org/linux/man-pages/man2/fsync.2.html

## Пример чтения

После mount пользователь выполняет cat /media/channel1/notes.txt. Программа открывает файл; ядро через FUSE обращается к TGFS; TGFS находит запись в индексе, загружает нужные части, проверяет их и возвращает байты. Если часть уже проверена и лежит в кэше, сеть не нужна.

## Пример будущей записи

Редактор передаёт новый текст через write. TGFS временно хранит его локально. При фиксации загружает части и новое оглавление, затем меняет указатель в superblock. Поэтому «write завершился» и «полная версия опубликована в Telegram» — разные моменты.

Нажатие «Сохранить» в редакторе может включать временный файл, fsync и rename; точное поведение зависит от редактора. Контракт записи TGFS пока не утверждён и не реализован.

## Что обсуждаем дальше

Зачем нужны и как связаны: заголовок тома -> оглавление -> запись файла -> части. Только после этого выбирать точные поля сообщений. Словарь не закрывает задачу #3: язык, FUSE-библиотека, гарантии и ошибки ещё требуют решений.
