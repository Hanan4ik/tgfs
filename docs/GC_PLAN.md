# Отчёт о совпадающем содержимом

`tgfs gc-plan` анализирует опубликованные версии в выбранном capture. Он
группирует непустые FILE_COMMIT по размеру и SHA-256, когда манифесты
ссылаются на разные наборы частей. Учитываются старые версии и файлы с
разными именами, UUID и схемами разбиения. Повтор того же operation_id
представлен первым исходным FILE_COMMIT. Отдельные CHUNK без манифеста
в отчёт не попадают.

```bash
./build/tgfs gc-plan "${tgfs_net[@]}" --capture ./capture-011
```

Для каждой группы скачиваются части каждой версии, проверяются ссылки,
размеры, SHA-256 отдельных частей и всего файла. При ошибке проверки
команда возвращает 1 и пишет причину в stderr. Успешный вывод JSON содержит
канал, UUID корня, boundary_id, статус покрытия scan и массив groups.
В каждой группе есть размер, SHA-256 и verified_commits с идентификаторами
commit_id, object_id, version_id и chunk_ids. Поле catalog_entries каждой
версии показывает пары parent_object_id и name из каталогов, достижимых
из корня. Имя относится к версии, которую выберет обычное чтение из этого
capture. Несколько имён одного файла перечисляются отдельно. Каталог
обходится один раз даже при нескольких путях к нему или цикле.

На верхнем уровне chunk_references показывает для каждой части из групп
все ID FILE_COMMIT из capture, в которых она указана. Сюда входят старые
версии и повторы одной операции. Список отражает ссылки манифестов,
а проверка содержимого относится к verified_commits.

## Прежние captures

Чтобы учесть сохранённый снимок, добавьте `--retain-capture DIRECTORY`.
Флаг можно повторять. Для каждого снимка требуется тот же канал, UUID корня
и start_id, а его boundary_id должен быть меньше текущего.

```bash
./build/tgfs gc-plan "${tgfs_net[@]}" --capture ./capture-011 \
    --retain-capture ./capture-008 --retain-capture ./capture-009
```

При этом scope получает значение provided_captures_only, а
retained_captures показывает путь, границу, статус покрытия и
commit_references каждого снимка. В commit_references входят все
FILE_COMMIT, которые ссылаются на CHUNK из текущих групп. Поле chunk_ids
показывает только пересечение с частями из этих групп. Поле catalog_entries
содержит имена, которые в данном старом снимке ведут к этой версии.
Исторический манифест учитывается и при пустом catalog_entries, и при
отсутствии записи CHUNK в старом журнале. При ошибке чтения или проверки
снимка команда завершится ошибкой. Сами данные исторических версий здесь
не скачиваются повторно.

Пустой массив groups означает, что
в этом capture не нашлось совпадающих полных комплектов с разными ссылками.

Это инвентаризация для задачи [#9](https://github.com/Hanan4ik/tgfs/issues/9).
Команда читает capture и документы через getChat/getFile, без удаления,
публикации и записи в постоянный кэш. Одинаковое содержимое может быть
доступно под несколькими именами, относиться к сохраняемой истории или
использовать общие части. Отчёт ограничен выбранной границей и не выдаёт
разрешение на удаление. Для физической очистки ещё нужны правила
сохранения истории и навигационных ссылок, учёт открытых файлов и intents,
проверка полноты списка сохранённых captures и координация с записью.
