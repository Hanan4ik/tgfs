# ADR-0001: транспорт Telegram

- Статус: **accepted**
- Дата: 2026-11-02
- Обсуждение: [#1](https://github.com/Hanan4ik/tgfs/issues/1)

## Контекст

Исходный запрос использует BotFather token, основной и null-канал. Нужны чтение, запись и восстановление без исходного компьютера. Необходимо решить, допустима ли пользовательская Telegram-сессия. Проверенные ограничения — в [TELEGRAM.md](../TELEGRAM.md).

## Варианты

| Вариант | Плюсы | Ограничения |
| --- | --- | --- |
| Cloud Bot API | Токен, простой HTTP, без своего API server | Небольшие части, нет обычной истории, recovery зависит от root refs и иногда staging |
| Local Bot API | Тот же bot-интерфейс, крупные uploads/downloads | Дополнительный сервис и credentials приложения; история не появляется |
| TDLib с user session | История и адресное чтение, удобнее исследовать импорт | Пользовательская авторизация/2FA, сессия и существенно иной жизненный цикл |
| TDLib с bot session | Доступ к некоторым MTProto-возможностям | Не считать способом автоматически снять ограничения bot-account; отдельное исследование |

## Принятое решение

Отделить transport interface от core. Выбран Bot API для первой версии из-за простоты реализации. Уточнение пользователя 2026-11-03: для первого прототипа выбран публичный Cloud Bot API по api.telegram.org, без собственного Bot API server. Предыдущий кандидат — cloud Bot API с explicit remote catalog и небольшими chunks; local API — опциональный профиль возможностей. TDLib user backend рассмотреть, если требуются история, импорт или отказ от пересылочного recovery.

Core оперирует типизированными refs, а не Bot API Message. Capabilities: download/upload limits, адресное получение записи, чтение истории, удаление, тип авторизации. Один URL не определяет capabilities. Backend читает согласованные версии формата, а миграция между backend требует адаптера refs.

## Основание и оставшиеся вопросы

2026-11-02 пользователь явно выбрал Bot API ради простоты реализации. TDLib отложен; второй backend сейчас не реализуем. Решение о транспорте принято, но не означает проверки всей схемы хранения.

Cloud/local для первого прототипа решён в пользу cloud. Импорт обычных каналов и работоспособность recovery остаются открытыми. Эксперимент #6 остаётся в backlog и проверяет технические предположения; он не блокирует фиксацию сделанного пользователем выбора.
